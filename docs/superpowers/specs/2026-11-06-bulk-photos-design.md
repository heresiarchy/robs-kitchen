# Bulk photo identification through ChatGPT scheduling
User chose to explore scheduled ChatGPT processing instead of separate model API billing. Implement the existing bulk-upload request with a website queue and linked hourly cloud task. Reuse the private Site, durable R2 uploads, import revisions, MCP image reads and stage_import writer. No external model API key or inference endpoint.

Upload up to 50 files sequentially with thumbnails, per-file progress and retry preserving operation IDs. Each file creates a durable pending import. New image uploads have empty text/items/recipe. The task reads those pending images, extracts names, metric pack quantities and only clearly printed dates, then fills the same draft. Images that cannot be read get source text beginning “Needs review:” so they do not repeat indefinitely. Never approve imports or change inventory automatically. Avoid duplicate imports and warn about multiple views of the same product.

Website shows waiting, identified and needs-review states, refreshes results, and removes the requirement to open ChatGPT manually. Keep the page open while files upload; after upload, processing works while closed. Task can run no more often than hourly and uses ChatGPT allowances. Verification must distinguish live MCP access from a real unattended execution. Check Site linked schedules before creating; preserve private access and existing records.
